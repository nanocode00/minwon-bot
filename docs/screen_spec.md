# 삼성생명 민원 지식 봇 — 화면 기획서

## 1. 화면 목적
공개·합성 FAQ를 검색해 참고 답변과 FAQ 번호를 함께 보여준다. 금액·보장 확정·범위 밖 질문은 답을 단정하지 않고 담당자 확인으로 전환한다.

## 2. 정보구조(IA)
1. 헤더: 서비스명, 교육용 데모 표기
2. 히어로: 핵심 가치와 질문 → FAQ → 담당자 확인 흐름
3. 면책 배너: 참고용 답변, 개인정보 입력 금지
4. 질문 카드: 입력창, 글자 수, 보안 경고, 실행 버튼
5. 결과 카드: 참고 답변, 카테고리, 담당자 확인 배지
6. 근거 FAQ: 첫 근거는 노출하고 추가 근거는 Accordion으로 접기
7. 이용 안내: 개인정보 예시와 서비스 범위를 하단 Accordion으로 접기

## 3. 핵심 흐름
질문 입력 → 입력·개인정보 검사 → 로딩 → 답변+근거 FAQ → 필요 시 담당자 확인. 검색 결과가 없거나 금액·해지환급·보장 여부가 포함되면 사람 확인을 우선한다.

## 4. 화면 상태 5종
| 상태 | 표현 | 다음 행동 |
|---|---|---|
| 초기 | 빈 입력창과 예시 질문, 빈 결과 안내 | 질문 입력 |
| 입력 중 | 글자 수, 보안 검사, 활성 버튼 | 수정 또는 실행 |
| 로딩 | 레이아웃 이동 없는 진행 바, aria-live 안내 | 중복 실행 방지 |
| 결과 | 답변 카드, FAQ 번호·카테고리·출처 | 새 질문 또는 근거 확인 |
| 오류·범위 밖 | 코랄 경고, 담당자 확인 필요 배지 | 질문 수정 또는 사람 확인 |

## 5. 컴포넌트
- 질문 입력창: label 상시 노출, 10~300자, placeholder는 예시만 제공
- 실행 버튼: “근거 FAQ 찾기”, 로딩 중 “FAQ를 찾는 중…”
- 답변 카드: 참고용 라벨, 답변, 카테고리, 새 질문 버튼
- 근거 FAQ 리스트: FAQ 번호, 질문, 출처를 읽기 순서대로 표시
- 담당자 확인 필요 배지: 코랄 배경과 텍스트를 함께 사용
- 면책 배너: “참고용 답변입니다. 금액·보장 여부는 담당자 확인이 필요합니다.”
- 상태 메시지: 일반 변화는 role=status, 차단 오류는 role=alert

## 6. UX 라이팅
| 위치 | 문구 |
|---|---|
| 제목 | 민원 질문, 근거부터 확인하세요 |
| 설명 | 공개·합성 FAQ를 찾아 참고 답변과 근거 번호를 함께 보여드립니다. |
| 입력 라벨 | 어떤 내용이 궁금하신가요? |
| 플레이스홀더 | 예: 보험금 청구에 필요한 서류가 궁금해요 |
| 실행 버튼 | 근거 FAQ 찾기 |
| 빈 상태 | 질문을 입력하면 관련 FAQ와 참고 답변이 여기에 표시됩니다. |
| 로딩 | 관련 FAQ와 근거를 확인하고 있습니다. |
| 입력 오류 | 질문을 10자 이상 입력해 주세요. |
| 개인정보 오류 | 개인정보로 보이는 숫자가 있습니다. 주민등록번호·계약번호·카드번호를 지워 주세요. |
| 범위 밖 | 확인 가능한 FAQ가 부족합니다. 정확한 안내를 위해 담당자 확인이 필요합니다. |
| 재시도 | 질문 다시 작성하기 |

톤은 짧고 차분하게 유지한다. 확정형보다 “FAQ 기준 참고 안내이며 실제 결과는 확인이 필요합니다”를 우선한다.

## 7. 접근성
- WCAG AA 대비, 색상 외 텍스트·기호로 상태를 중복 전달
- DOM 읽기 순서와 시각 순서를 헤더 → 면책 → 질문 → 상태 → 답변 → 근거로 일치
- 모든 조작 요소는 키보드 접근 가능하며 focus-visible 윤곽선 제공
- 터치 대상 최소 44×44px, 모바일 우선 1열 구성
- 로딩은 aria-live=polite, 오류는 role=alert
- prefers-reduced-motion에서 애니메이션 제거

## 8. 보안
- 주민등록번호 형식, 12자리 이상 연속 숫자, 카드번호형 숫자를 입력 중 즉시 차단
- 실제 연동 시 서버에서도 재검사하고 입력·키·응답 원문을 로그에 남기지 않음
- Supabase publishable 키만 클라이언트에서 사용하고 secret/service-role 키는 금지
- 금액·확정 판단·자동 발송 기능은 제공하지 않음
